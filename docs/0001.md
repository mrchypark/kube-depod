# **kube-depod 설계 문서 (Design Specification)**

**버전:** v0.1
**작성자:**
**목적:** Pod annotation + DepodPolicy CRD 기반 자동 정리(물리 삭제) 오퍼레이터 설계 정의

---

# 1. 개요 (Overview)

kube-depod는 Kubernetes 환경에서 Pod에 부여된 annotation과 사용자 정의 CRD(DepodPolicy)를 기반으로 Pod 제거 정책을 자동으로 실행하는 오퍼레이터입니다.
운영자는 DepodPolicy로 “조건(Condition)”을 선언적으로 정의하고, 애플리케이션 Pod에는 어떤 정책을 적용할 것인지 annotation으로만 지정합니다.

본 문서는 아키텍처, CRD 설계, 정책 엔진, 조건 평가 방식, 컨트롤러 플로우, 안전장치 및 구현 개요를 포함합니다.

---

# 2. 목표 및 요구사항 (Goals & Requirements)

## 2.1 기능 요구사항

* Pod annotation 기반 정책 활성화
* DepodPolicy CRD에 조건식(표현식)을 정의
* 조건이 만족될 경우 Pod 삭제(Evict/Delete) 수행
* 조건식에는 다음 포함 가능:

  * 필드 값 비교
  * 논리 연산 (AND/OR)
  * 시간 비교 (TTL, timestamp)
  * annotation 값 기반 조건
* 향후 확장 가능하도록 표현식 엔진 추상화

## 2.2 비기능 요구사항

* Kubernetes API와의 높은 안정성
* 예측 가능한 Reconciliation 동작
* 과도한 삭제 방지를 위한 rate limiting
* system namespace 보호
* dryRun 지원
* Metrics 및 로깅 제공

## 2.3 기술적 선택

* 언어: **Rust**
* 프레임워크: **kube-rs**
* 표현식 엔진: **cel-rust** (v0.11.6 이상, CEL 공식 사양 구현)
* 리소스 정의: `k8s-openapi`, `kube::CustomResource`
* 런타임: Tokio (async/await)

# 4. CRD 설계 (DepodPolicy)

### 4.1 CRD 구조

```yaml
apiVersion: kube-depod.io/v1alpha1
kind: DepodPolicy
metadata:
  name: example-ttl-policy
spec:
  target:
    namespaceSelector:
      matchNames: ["default"]
    podSelector:
      matchLabels:
        app: my-app

  trigger:
    annotationKey: "kube-depod/policy"
    annotationValues:
      - "ttl-10m"

  condition:
    type: "CEL"
    expression: "now - metadata.creationTimestamp > duration('10m')"

  action:
    type: "Delete"
    gracePeriodSeconds: 30
    dryRun: false

  limits:
    maxDeletesPerMinute: 20
    protectSystemNamespaces: true
    excludedNamespaces:
      - monitoring
      - logging
```

### 4.2 설계 포인트

* **target**: 정책을 적용할 Pod 범위를 제한하여 오작동 위험 최소화
* **trigger**: Pod annotation이 정책 이름과 일치할 때만 활성
* **condition.type**: CEL 외에 향후 Builtin/JsonPath 등 다양화 가능
* **action.type**: Delete/Evict/Annotate 등 확장성 확보
* **limits**: 실수로 인한 대량 삭제 방지

# 5. 표현식 엔진 (Expression Engine)

정책 조건식은 cel-rust를 통해 평가합니다.

## 5.1 cel-rust 개요

**cel-rust**는 Google의 CEL(Common Expression Language) 사양을 Rust로 구현한 인터프리터입니다.

* Kubernetes 공식 정책 언어(CEL)와 동일한 사양 준수
* Rust 환경에서 높은 성능과 안전성 제공
* 선언적 방식의 정책 정의에 최적화
* 타입 검사 및 런타임 안전성 보장
* 사용자 정의 함수 확장 가능

## 5.2 CEL 표현식 예제

### 필드 비교

```cel
metadata.namespace == "default"
```

### 시간 기반 조건

```cel
now - metadata.creationTimestamp > duration("10m")
```

### 목록 연산 (all, any, map)

```cel
// Pod의 모든 container가 ready 상태인지 확인
status.containerStatuses.all(c, c.ready == true)

// restart count 검사
status.containerStatuses.any(c, c.restartCount > 5)
```

### annotation 기반 조건

```cel
object.metadata.annotations["team"] == "qa"
```

### 복합 조건

```cel
status.phase == "Failed" && status.containerStatuses[0].restartCount > 3
```

## 5.4 Pod 객체와 CEL 통합

Pod 객체를 cel-rust의 Context에 로드하여 표현식 평가:

```rust
use cel::{Context, Program};
use serde_json::Value;

fn evaluate_pod_condition(pod_json: &str, expression: &str) -> Result<bool, String> {
    // 1. CEL 프로그램 컴파일 및 타입 검사
    let program = Program::compile(expression)
        .map_err(|e| format!("Compile error: {}", e))?;

    // 2. Pod JSON을 Value로 파싱
    let pod_value: Value = serde_json::from_str(pod_json)
        .map_err(|e| format!("JSON parse error: {}", e))?;

    // 3. 실행 컨텍스트 생성
    let mut context = Context::default();
    
    // Pod 객체를 'object' 변수로 등록
    context.add_variable("object", pod_value.clone());

    // 4. 표현식 실행
    let result = program.execute(&context)
        .map_err(|e| format!("Execution error: {}", e))?;

    // 5. 결과를 boolean으로 변환
    result.as_bool()
        .ok_or_else(|| "CEL expression must return boolean".to_string())
}

// 사용 예시
#[tokio::main]
async fn main() -> Result<()> {
    let pod_json = r#"{
        "apiVersion": "v1",
        "kind": "Pod",
        "metadata": {
            "name": "example-pod",
            "namespace": "default",
            "creationTimestamp": "2025-11-15T10:00:00Z"
        },
        "status": {
            "phase": "Failed",
            "containerStatuses": [
                {
                    "name": "app",
                    "ready": false,
                    "restartCount": 5
                }
            ]
        }
    }"#;

    // Pod가 5번 이상 restart된 경우 확인
    let expr = "object.status.containerStatuses[0].restartCount > 3";
    match evaluate_pod_condition(pod_json, expr) {
        Ok(true) => println!("Condition matched: pod will be deleted"),
        Ok(false) => println!("Condition not matched: pod will be kept"),
        Err(e) => eprintln!("Evaluation error: {}", e),
    }

    Ok(())
}
```

## 5.5 CEL 함수 라이브러리 확장

Kubernetes 운영에 유용한 커스텀 함수:

```rust
use cel::{Context, Program};
use chrono::{Duration, Utc};

fn create_context_with_k8s_functions() -> Context {
    let mut context = Context::default();

    // 현재 시각 (Unix timestamp)
    context.add_function("now", || {
        Utc::now().timestamp()
    });

    // 두 timestamp 간 차이 (초 단위)
    context.add_function("age_seconds", |created: i64| -> i64 {
        Utc::now().timestamp() - created
    });

    // 문자열이 특정 prefix로 시작하는지 확인
    context.add_function("starts_with", |s: String, prefix: String| -> bool {
        s.starts_with(&prefix)
    });

    // Pod phase 확인
    context.add_function("is_failed", |phase: String| -> bool {
        phase == "Failed" || phase == "Unknown"
    });

    context
}

// 사용 예시
fn main() {
    let program = Program::compile(
        "age_seconds(object.metadata.creationTimestamp) > 600"
    ).unwrap();

    let context = create_context_with_k8s_functions();
    let result = program.execute(&context).unwrap();
    
    println!("Pod older than 10 minutes: {}", result.as_bool().unwrap());
}
```

# 6. 오퍼레이터 동작 방식 (Reconciliation Flow)

## 6.1 이벤트 흐름

1. Pod 감지 (watch)
2. DepodPolicy 캐시 로드
3. 해당 Pod가 어떤 정책 대상인지 필터링
4. trigger 조건(annotation) 검사
5. CEL 조건식 평가
6. 삭제 가능 여부(rate limit, 보호 네임스페이스) 검사
7. action(Delete/Evict) 실행
8. 상태 업데이트 및 metrics 기록

## 6.2 Rust 기반 구현 패턴

### Reconciler 핸들러

```rust
use kube::{Api, Client};
use kube::runtime::controller::{Action, Controller};
use cel::{Context, Program};
use serde_json::to_value;
use std::sync::Arc;
use std::time::Duration;

async fn reconcile(pod: Arc<Pod>, ctx: Arc<Context>) -> Result<Action> {
    let namespace = pod.namespace().unwrap_or_default();
    
    // 1. 정책 규칙 캐시에서 일치하는 규칙 조회
    let rules = ctx.policy_cache.match_pod(&pod);

    for rule in rules {
        // 2. trigger 조건 검사 (annotation 확인)
        if !rule.trigger.matches(&pod) {
            continue;
        }

        // 3. CEL 조건식 평가
        match evaluate_condition(&rule.spec.condition, &pod)? {
            false => continue,
            true => {
                tracing::debug!("Condition matched for rule: {}", rule.name);
            }
        }

        // 4. rate limiting 검사
        if ctx.limiter.exceeded(&rule) {
            tracing::warn!("Rate limited for rule {}", rule.name);
            continue;
        }

        // 5. 시스템 네임스페이스 보호
        if rule.spec.limits.protect_system_namespaces && is_system_namespace(&namespace) {
            tracing::warn!("Cannot delete pod in protected namespace: {}", namespace);
            continue;
        }

        // 6. action 실행
        if rule.spec.action.action_type == ActionType::Delete {
            if !rule.spec.action.dry_run {
                let api = Api::<Pod>::namespaced(ctx.client.clone(), &namespace);
                api.delete(&pod.name_unchecked(), &Default::default()).await?;
                tracing::info!("Deleted pod: {}/{}", namespace, pod.name_unchecked());
                ctx.metrics.deleted_pods_total.with_label_values(&[&rule.name]).inc();
            } else {
                tracing::info!("[DRY_RUN] Would delete pod: {}/{}", namespace, pod.name_unchecked());
            }
        }
    }

    // 30초 후 재조정
    Ok(Action::requeue(Duration::from_secs(30)))
}

/// CEL 표현식으로 조건 평가
fn evaluate_condition(condition: &PolicyCondition, pod: &Pod) -> Result<bool> {
    // 1. CEL 프로그램 컴파일 (캐시되어야 함)
    let program = Program::compile(&condition.expression)
        .map_err(|e| format!("Failed to compile CEL: {}", e))?;

    // 2. Pod 객체를 JSON으로 변환
    let pod_value = to_value(pod)
        .map_err(|e| format!("Failed to convert pod to JSON: {}", e))?;

    // 3. 실행 컨텍스트 생성 및 변수 추가
    let mut context = Context::default();
    context.add_variable("object", pod_value);
    
    // 필요한 helper 함수 등록
    context.add_function("now", || chrono::Utc::now().timestamp());

    // 4. 표현식 실행
    let result = program.execute(&context)
        .map_err(|e| format!("Failed to execute CEL: {}", e))?;

    // 5. 결과를 boolean으로 변환
    result.as_bool()
        .ok_or_else(|| "CEL result is not a boolean".to_string())
}
```

### DepodPolicy 구조 (Kubernetes CRD)

```rust
use kube::CustomResource;
use serde::{Deserialize, Serialize};

#[derive(CustomResource, Clone, Debug, Serialize, Deserialize)]
#[kube(group = "kube-depod.io", version = "v1alpha1", kind = "DepodPolicy")]
#[kube(namespaced)]
pub struct DepodPolicySpec {
    pub target: PodSelector,
    pub trigger: Trigger,
    pub condition: PolicyCondition,
    pub action: Action,
    pub limits: Limits,
}

#[derive(Debug, Serialize, Deserialize, Clone)]
pub struct PolicyCondition {
    /// CEL 표현식
    pub expression: String,
}

#[derive(Debug, Serialize, Deserialize, Clone)]
pub struct Action {
    #[serde(rename = "type")]
    pub action_type: ActionType,
    pub grace_period_seconds: Option<i32>,
    pub dry_run: bool,
}

#[derive(Debug, Serialize, Deserialize, Clone, PartialEq)]
pub enum ActionType {
    Delete,
    Evict,
}

#[derive(Debug, Serialize, Deserialize, Clone)]
pub struct Limits {
    pub max_deletes_per_minute: u32,
    pub protect_system_namespaces: bool,
    pub excluded_namespaces: Option<Vec<String>>,
}
```

### DepodPolicy 적용 로직 (Rust)

```rust
use std::collections::HashSet;

/// 네임스페이스가 보호되어야 하는지 확인
fn is_namespace_protected(
    namespace: &str,
    rule_limits: &Limits,
) -> bool {
    // 1. 시스템 네임스페이스 확인
    let system_namespaces = vec![
        "kube-system",
        "kube-public",
        "kube-node-lease",
        "kube-node-lease",
    ];

    if rule_limits.protect_system_namespaces 
        && system_namespaces.contains(&namespace) {
        return true;
    }

    // 2. 커스텀 제외 네임스페이스 확인
    if let Some(excluded) = &rule_limits.excluded_namespaces {
        if excluded.contains(&namespace.to_string()) {
            return true;
        }
    }

    false
}

/// Reconcile 함수에서의 사용
async fn reconcile(pod: Arc<Pod>, ctx: Arc<Context>) -> Result<Action> {
    let namespace = pod.namespace().unwrap_or_default();
    let rules = ctx.policy_cache.match_pod(&pod);

    for rule in rules {
        if !rule.trigger.matches(&pod) {
            continue;
        }

        if !evaluate_condition(&rule.spec.condition, &pod)? {
            continue;
        }

        if ctx.limiter.exceeded(&rule) {
            tracing::warn!("Rate limited for rule {}", rule.name);
            continue;
        }

        // 네임스페이스 보호 확인 (시스템 NS + 커스텀 제외 NS)
        if is_namespace_protected(&namespace, &rule.spec.limits) {
            tracing::warn!(
                "Namespace '{}' is protected by rule '{}'",
                namespace,
                rule.name
            );
            continue;
        }

        if rule.spec.action.action_type == ActionType::Delete {
            if !rule.spec.action.dry_run {
                let api = Api::<Pod>::namespaced(ctx.client.clone(), &namespace);
                api.delete(&pod.name_unchecked(), &Default::default()).await?;
                tracing::info!(
                    "Deleted pod: {}/{} (rule: {})",
                    namespace,
                    pod.name_unchecked(),
                    rule.name
                );
                ctx.metrics
                    .deleted_pods_total
                    .with_label_values(&[&rule.name])
                    .inc();
            }
        }
    }

    Ok(Action::requeue(Duration::from_secs(30)))
}
```

# 7. 안전장치 (Safety Mechanisms)

### 7.1 rate limiting

* per-rule 또는 global 단위로 분당 삭제 가능 수 제한
* Redis/Local in-memory rate limiter 적용 가능

### 7.2 보호 네임스페이스

#### 시스템 네임스페이스 (자동 보호)

기본적으로 삭제 금지:

* kube-system
* kube-public
* kube-node-lease
* 자동으로 생성된 core 서비스

#### 커스텀 제외 네임스페이스 (excludedNamespaces)

DepodPolicy의 `limits.excludedNamespaces` 설정으로 추가 보호 가능:

```yaml
limits:
  protectSystemNamespaces: true
  excludedNamespaces:
    - monitoring
    - logging
    - critical-apps
```

이 경우 DepodPolicy이 `monitoring`, `logging`, `critical-apps` 네임스페이스의 Pod을 삭제하지 않습니다.

### 7.3 dryRun

* 조건식 평가만 수행
* 실제 삭제는 하지 않음
* 정책 검증 단계에 유용

### 7.4 Operator-level Fail-safe

* 연속 에러 발생 시 backoff
* 연결 실패 시 exponential retry
* 정책 평가 실패 시 Pod 삭제 금지

# 12. 추가 고려사항

## CEL 표현식 최적화

1. **표현식 캐싱**: 동일한 표현식이 반복 실행되므로 컴파일된 Program을 캐시
2. **변수 프리페칭**: Pod 객체를 JSON으로 변환하는 오버헤드 최소화
3. **연산 순서**: 빠른 실패(short-circuit) 활용으로 불필요한 평가 방지

## 보안

* CEL은 샌드박스 언어로 설계됨 (무한 루프 불가능)
* 동적 코드 실행이 없으므로 injection 위험 없음
* DepodPolicy은 RBAC으로 제어 필수

## 모니터링

* 각 정책 실행 시간 기록 (느린 표현식 추적)
* CEL 컴파일 에러 로깅
* 정책 매칭 및 삭제 통계

## 성능 예상

* **CEL 컴파일**: ~1ms (캐시 전제)
* **표현식 평가**: ~0.1-0.5ms (표현식 복잡도에 따라)
* **Pod 삭제 API 호출**: ~100-500ms (네트워크 지연)
