# **kube-depod 설계 문서 (Design Specification)**

**버전:** v0.1
**작성자:**
**목적:** Pod annotation + PolicyRule CRD 기반 자동 정리(물리 삭제) 오퍼레이터 설계 정의

---

# 1. 개요 (Overview)

kube-depod는 Kubernetes 환경에서 Pod에 부여된 annotation과 사용자 정의 CRD(PolicyRule)를 기반으로 Pod 제거 정책을 자동으로 실행하는 오퍼레이터입니다.
운영자는 PolicyRule로 “조건(Condition)”을 선언적으로 정의하고, 애플리케이션 Pod에는 어떤 정책을 적용할 것인지 annotation으로만 지정합니다.

본 문서는 아키텍처, CRD 설계, 정책 엔진, 조건 평가 방식, 컨트롤러 플로우, 안전장치 및 구현 개요를 포함합니다.

---

# 2. 목표 및 요구사항 (Goals & Requirements)

## 2.1 기능 요구사항

* Pod annotation 기반 정책 활성화
* PolicyRule CRD에 조건식(표현식)을 정의
* 조건이 만족될 경우 Pod 삭제(Evict/Delete) 수행
* 조건식에는 다음 포함 가능:

  * 필드 값 비교
  * 논리 연산 (AND/OR)
  * 시간 비교 (TTL, timestamp)
  * annotation 값 기반 조건
* 향후 확장 가능하도록 표현식 엔진 추상화

## 2.2 비기능 요구사항

* Kubernetes API와의 높은 안정성
* 예측 가능한 Reconciliation 동작
* 과도한 삭제 방지를 위한 rate limiting
* system namespace 보호
* dryRun 지원
* Metrics 및 로깅 제공

## 2.3 기술적 선택

* 언어: **Rust**
* 프레임워크: **kube-rs**
* 표현식 엔진: **cel-rust** (조건식 평가)
* 리소스 정의: `k8s-openapi`, `kube::CustomResource`

kube-depod의 전체 구성은 다음과 같습니다.

```
┌────────────────────────────────────────┐
│              PolicyRule CRD           │
│   - 조건식 (CEL)                      │

└────────────────────────────────────────┘
                  │
                  ▼
┌────────────────────────────────────────┐
│            kube-depod Operator         │
│                                        │
│  1. Pod 이벤트 감지                    │

│  5. Rate Limiting / DryRun            │
└────────────────────────────────────────┘
                  │
                  ▼
          Kubernetes API Server
```

# 4. CRD 설계 (PolicyRule)

### 4.1 CRD 구조

```yaml
apiVersion: kube-depod.io/v1alpha1
kind: PolicyRule
metadata:
  name: example-ttl-policy
spec:
  target:
    namespaceSelector:
      matchNames: ["default"]
    podSelector:
      matchLabels:
        app: my-app

  trigger:
    annotationKey: "kube-depod/policy"
    annotationValues:
      - "ttl-10m"

  condition:
    type: "CEL"
    expression: "now - metadata.creationTimestamp > duration('10m')"

  action:
    type: "Delete"
    gracePeriodSeconds: 30
    dryRun: false

  limits:
    maxDeletesPerMinute: 20
    protectSystemNamespaces: true
```

### 4.2 설계 포인트

* **target**: 정책을 적용할 Pod 범위를 제한하여 오작동 위험 최소화
* **trigger**: Pod annotation이 정책 이름과 일치할 때만 활성
* **condition.type**: CEL 외에 향후 Builtin/JsonPath 등 다양화 가능
* **action.type**: Delete/Evict/Annotate 등 확장성 확보
* **limits**: 실수로 인한 대량 삭제 방지

# 5. 표현식 엔진 (Expression Engine)

정책 조건식은 cel-rust를 통해 평가합니다.

## 5.1 사용 이유

* Kubernetes 공식 정책 언어(CEL)와 동일
* Rust 환경에서 사용 가능
* 선언적 방식의 정책 정의에 적합
* 비교/논리/시간 연산 지원

## 5.2 지원 기능 예시

### 비교(expression)

```cel
metadata.namespace == "default"
```

### 시간 연산

```cel
now - metadata.creationTimestamp > duration("10m")
```

### annotation 기반 조건

```cel
object.metadata.annotations["team"] == "qa"
```

### 복합 조건

```cel
status.phase == "Failed" && status.containerStatuses[0].restartCount > 3
```

# 6. 오퍼레이터 동작 방식 (Reconciliation Flow)

## 6.1 이벤트 흐름

1. Pod 감지 (watch)
2. PolicyRule 캐시 로드
3. 해당 Pod가 어떤 정책 대상인지 필터링
4. trigger 조건(annotation) 검사
5. CEL 조건식 평가
6. 삭제 가능 여부(rate limit, 보호 네임스페이스) 검사
7. action(Delete/Evict) 실행
8. 상태 업데이트 및 metrics 기록

## 6.2 Rust 기반 pseudo code

```rust
async fn reconcile(pod: Arc<Pod>, ctx: Arc<Context>) -> Result<Action> {
    let rules = ctx.policy_cache.match(&pod);

    for rule in rules {
        if !rule.trigger.matches(&pod) {
            continue;
        }

        if !rule.evaluate_cel(&pod)? {
            continue;
        }

        if ctx.limiter.exceeded(&rule) {
            log::warn!("Rate limited for rule {}", rule.name);
            continue;
        }

        if rule.spec.action.type == ActionType::Delete {
            if rule.spec.limits.protect_system_namespaces && is_system_ns(&pod) {
                continue;
            }
            if !rule.spec.action.dry_run {
                ctx.client.delete(&pod, &Default::default()).await?;
            }
        }
    }

    Ok(Action::requeue(Duration::from_secs(30)))
}
```

# 7. 안전장치 (Safety Mechanisms)

### 7.1 rate limiting

* per-rule 또는 global 단위로 분당 삭제 가능 수 제한
* Redis/Local in-memory rate limiter 적용 가능

### 7.2 보호 네임스페이스

기본적으로 삭제 금지:

* kube-system
* kube-public
* kube-node-lease
* 자동으로 생성된 core 서비스

### 7.3 dryRun

* 조건식 평가만 수행
* 실제 삭제는 하지 않음
* 정책 검증 단계에 유용

### 7.4 Operator-level Fail-safe

* 연속 에러 발생 시 backoff
* 연결 실패 시 exponential retry
* 정책 평가 실패 시 Pod 삭제 금지

# 9. 구현 계획 (Roadmap)

## Phase 1 — Minimal MVP

* PolicyRule CRD 정의
* annotation 기반 trigger
* Builtin TTL 조건식(코드 기반)
* Pod 삭제 기능
* dryRun
* 기본 로그

## Phase 2 — CEL 조건식 도입

* cel-rust 기반 조건 엔진 적용
* JSON 변환, Pod struct 매핑
* expression test suite 구성

## Phase 3 — 운영 기능 추가

* metrics
* rate limiting
* protectSystemNamespaces
* 삭제 행위 히스토리 추적

## Phase 4 — 확장

* Evict 지원
* Label/Annotation 자동 추가
* Multi-policy support
* Policy 상태/status 필드 확장
